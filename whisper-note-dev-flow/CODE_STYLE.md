# 代码风格与工程约定 · apigx

> 由开发流程维护（§5）。Google Go Style 为主，下列为本项目在实战中反复验证过的补充约定。

## 一、改文件：先读真实文本，改完必须校验

- **禁止凭记忆写补丁锚点**。`gofmt` / Prettier 会重排空格与对齐，锚点极易失效。
- 补丁脚本**必须校验**：替换后检查目标文本确实存在，否则拒绝写盘并报错。
  > 教训：曾出现"脚本打印成功但替换静默未生效"，导致接口字段为 `nil`，靠用例才发现。
- 含引号/反引号/模板串的代码，**不要用 shell here-string 承载**（PowerShell 会破坏转义）；
  改为用文件写入（`write`）或写入独立文件（如新 `.go` 文件）。
- 写库 SQL 同理：**先读列定义与外键**，再写语句；JSON 值用文件 + `psql -f`，不要经过 shell 引号。

## 二、测试与断言

- **取数据要按身份，不按下标/顺序**。列表常按 `id DESC`，用 `items[0]` 会取错行。
- 断言要先确认**语义**再写：曾把"3 条候选"写死，而幂等去重后实际是 2 条。
- 并发相关的**安全属性必须有用例**：如"并发兑换单次邀请只能有一个成功"。
- 既有用例断言的是**产品口径**：改动使它失败时，**先假设测试是对的**，再论证是否真的要改口径。
  > 教训：曾把广场判据改成"公开 或 本人所有"，被既有用例拦下 —— 广场是发现面，所有者看自己的东西走「我的分享」。

## 三、领域约定（apigx）

- **两套枚举不可混用**：邀请范围 `1=分组/2=供给`，授权资源 `0=分组/1=供给`。转换必须显式。
- `apigx_*` 表的软删是 `alive_flag = 本行 ID` + `deleted_at timestamptz`（**不是** epoch 整数）；
  底座 `channels` **没有**软删列（硬删除），且 `tasks.channel_id` 有外键，删渠道前必须先清引用它的任务。
- **凭证只存哈希**，明文只在创建响应里出现一次，**不得**进入列表接口、日志与错误信息。
- 授权/邀请类接口的越权一律返回 **404**（不确认"资源存在但不属于你"），失败原因不区分以防枚举。

## 四、收录纪律

- 未验证的内容**不得**写成"已验证"；失败与回退必须如实记录（含"未解"）。
- 每个上游改动登记到 `docs/stage0/upstream-diff.md`（D-编号）。
