**验证**：
- 底座在本地 PG 5433 + Redis 6379 上启动成功，自动建表 **37 张**，`GET /api/status` → 200；
- `POST /v1/chat/completions` 经替身上游返回 **200**，替身取证确认上游 Key 指纹为配置值、**平台扩展头未泄漏**、上游收到正确模型名；
- 5 项验收实验：**② 定向渠道/Key 不被二次抽选 PASS**（定向 6/6，另一渠道 Key 零出现）；**③ 正成本估算 PASS**（单次 1725 ≈ ＄0.00345）+ 零余额 403 确认前置条件存在；**④ 预算准入 PASS**（额度 20000 下并发 6 个恰好 1 个通过、余额未被击穿）+ 并发上限确认缺失；**①** 用户/令牌隔离 PASS、渠道归属缺失；**⑤** 路由鉴权 PASS、端到端归属未取证；
- 设计文档全部代码引用回源核对：**279/279 命中，0 越界 0 缺失**；
- `relaykit` 独立构建通过（`GOWORK=off`）；`go build ./...`、`bun run build` 全绿。

**剩余风险**：
1. **TD-07**（平台 Key 明文查找 vs 只存摘要）与 **TD-08**（指定渠道分支绕过 token 模型限制）必须在写第一行业务代码前解决——已实证，方案已给出；
2. **TD-09/TD-10**：`TrustQuota` 旁路与 `FreeModel` 短路会影响 `usage_only` 与容量预留的正确性；
3. **磁盘**：D 盘 98.9% 已用，会触发底座自身的 `503 system_disk_overloaded`，且三库矩阵还需要空间；
4. **未核实项**：底座缺少统一的供给能力声明；`service/authz` 的 Permission 语义未读；任务取消能力未确认；
5. 全部结论来自**替身 + 源码阅读**，无真实上游、无压测、无安全审计；阶段 3 排期受真实凭据到位时点支配。
