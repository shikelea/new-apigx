# 技术债台账

阶段 0 · T0.11 产出。用户 2026-09-16 要求「初期就把整体架构规划与可维护性做对」，本文是该要求的可执行落点。

**使用规则**
1. 每条技术债必须有：可执行的偿还动作 + 明确的触发条件。不接受「以后再看看」。
2. 每个阶段结束（阶段 0/1/2/3/4 收口）必须复查本台账：更新状态、补新发现的条目。
3. 新增条目只能追加，不得删除历史；状态改为「已偿还」时写明偿还证据。

**状态取值**：`未偿还` / `缓解中` / `已偿还` / `已接受`（明确选择长期承受，需写明理由）。

## 四、下一阶段需要继续盯的风险

1. **TD-07 与 TD-08 是必须在写第一行业务代码前解决的**：前者决定平台 Key 的存储形态，后者是既有授权缺陷，两者都会影响后续所有接口。
2. **`apigx/` 目录的重建能力**：底座升级回滚依赖「`apigx/` 可独立重建」，阶段 1 结束时必须验证一次（在干净克隆上只应用 `apigx/` 与接线一行，能构建通过）。
3. **三库矩阵的执行成本**：第一次迁移落地时就会暴露真实成本，届时应重新评估 TD-02 的口径。
